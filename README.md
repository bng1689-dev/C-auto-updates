# CRIMES AUTO — ช่องทางแจกจ่ายอัปเดต (release channel)

รีโปนี้คือ **ช่องทางที่โปรแกรม CRIMES AUTO บนเครื่องผู้ใช้ใช้ตรวจสอบและดาวน์โหลดอัปเดต**
ไม่ใช่ที่พัฒนาโค้ดแบบปกติ — โค้ดของโปรแกรมทั้งหมดอยู่ *ในแพ็กเกจ zip* ของแต่ละรุ่น
และรุ่นล่าสุดถูกประกาศผ่าน `update-manifest.json`

| ที่ | คืออะไร |
|---|---|
| `update-manifest.json` | ประกาศรุ่นล่าสุด (เวอร์ชัน · URL zip · sha256 · เปิดให้ทุกคนอัปเดตไหม · บันทึกรุ่น) — **โปรแกรมทุกเครื่องอ่านไฟล์นี้** |
| `CRIMES_AUTO_update_vX.Y.Z.zip` | แพ็กเกจของแต่ละรุ่น (โค้ด `app/` + สคริปต์อัปเดต) เก็บไว้ทุกรุ่นเพื่อย้อนดู/ติดตั้งมือได้ |
| `CHANGELOG.md` | บันทึกการเปลี่ยนแปลงทุกรุ่น (สร้างจากประวัติ manifest) |
| `tests/` | ชุดทดสอบทั้งหมด — รันกับแพ็กเกจรุ่นล่าสุดจริง ๆ (ดูหัวข้อทดสอบ) |
| `tools/release.py` | เครื่องมือปล่อยรุ่น: แตกแพ็กเกจ → สร้าง zip+manifest → ตรวจของออนไลน์ |
| `tools/changelog.py` | สร้าง `CHANGELOG.md` ใหม่ทั้งไฟล์จากประวัติ git |
| `tools/hub_gas.js` | สคริปต์ศูนย์กลางรวมตัวเลข (Google Apps Script) — **ไม่ถูกแจกไปกับโปรแกรม** ([คู่มือ](tools/README.md)) |
| `build/` (ไม่ขึ้น git) | ทรีที่แตกจากแพ็กเกจรุ่นล่าสุด ใช้แก้โค้ดและทดสอบก่อนปล่อยรุ่นถัดไป |
| `.github/workflows/tests.yml` | CI รันชุดทดสอบทั้งหมดทุก PR และทุกครั้งที่ push เข้า `main` |

## การอัปเดตทำงานอย่างไร

1. โปรแกรมบนเครื่องผู้ใช้อ่าน `update-manifest.json` จาก URL ในการตั้งค่า (ค่าเริ่มต้นชี้มาที่ `main` ของรีโปนี้)
2. ถ้า `version` ใหม่กว่าที่ติดตั้ง **และผู้ใช้มีสิทธิ์อัปเดต** จะขึ้นแจ้งเตือน "มีรุ่นใหม่" พร้อม `notes`
3. กดอัปเดต → ดาวน์โหลด zip จาก `url` → **ตรวจ sha256 ต้องตรง** → เรียก `Update.ps1` ในแพ็กเกจ
4. `Update.ps1` ปิดโปรแกรม/Chrome ของระบบที่ค้าง, สำรอง `data.db`, แล้ว **วางทับเฉพาะโฟลเดอร์ `app/`**
   (robocopy แบบ merge) โดยไม่แตะ `app/backend/data/` และ `app/backend/uploads/` — บัญชี ประวัติ การตั้งค่า อยู่ครบ
   ไฟล์ที่รุ่นใหม่ไม่มีแล้วจะ *ไม่ถูกลบ* ออกจากเครื่อง (จึงมีไฟล์เก่าค้างได้ เช่น `licensekey.py`)

### รูปแบบ `update-manifest.json`

| ฟิลด์ | ความหมาย |
|---|---|
| `version` | เลขรุ่น `X.Y.Z` — เทียบเป็นตัวเลขทีละส่วน |
| `url` | ที่อยู่ zip (ต้องเป็นไฟล์ในรีโปนี้บน `main`) |
| `sha256` | แฮชของ zip — โปรแกรมปฏิเสธไฟล์ที่แฮชไม่ตรง |
| `open` | `true` = **รุ่นนี้เปิดให้ทุกเครื่องอัปเดตโดยไม่ต้องได้รับสิทธิ์** (ใช้ตอนต้องดึงทุกเครื่องขึ้นรุ่นเดียวกัน เช่น v3.3.0/v3.4.0) · `false` = ตามสิทธิ์ปกติ |
| `notes` | บันทึกรุ่นที่แสดงในโปรแกรม — คั่นหัวข้อด้วย ` · ` (ใช้แยกเป็นรายการใน CHANGELOG ด้วย) |

### สิทธิ์อัปเดต (ตั้งแต่ v3.1.0)

- **Super Admin** อัปเดตได้เสมอ
- สมาชิกอัปเดตได้เมื่อ Super Admin **เปิดสิทธิ์ "อัปเดตโปรแกรม"** ให้ในหน้า *สมาชิก & ทีม* (ปุ่มสลับในแถวของแต่ละคน)
  สมาชิกที่ไม่มีสิทธิ์จะ *ไม่เห็นแจ้งเตือน* รุ่นใหม่เลย
- รุ่นที่ manifest ประกาศ `"open": true` ข้ามกติกาข้อบนรอบเดียว
- ระบบ KEY (v2.8.0–v3.0.0) ถูกยกเลิกแล้ว — `tools/keygen.py` ถูกลบออกจากรีโป (ดูได้ในประวัติ git ถ้าจำเป็น)

> เพราะแต่ละเครื่องมีฐานข้อมูลของตัวเอง สิทธิ์อัปเดตจึงเป็นเรื่องของเครื่องนั้น ๆ
> การประสานงาน "ทุกเครื่อง" ทำได้ทางเดียวคือ `open` ใน manifest

### ลืมรหัสผ่าน — สมาชิก (ตั้งแต่ v3.6.4)

สมาชิกกด **ลืมรหัสผ่าน?** ใต้หน้าเข้าสู่ระบบ แล้วยืนยันตัวตนด้วย **ชื่อที่ใช้เข้าเว็บ CRIMES** — ต้องตรงกับชื่อบัญชีที่โปรแกรม
**อ่านจากหน้าเว็บ CRIMES** ตอนคนนั้นเข้าระบบค้น (ตาราง `crimes_accounts` · ไม่สนตัวพิมพ์ใหญ่-เล็ก/ช่องว่างหัวท้าย) จึงตั้งรหัสผ่านใหม่
และเข้าสู่ระบบได้ทันที · ค่าที่ผู้ใช้กรอกเองในช่อง "บัญชี CRIMES ผู้ค้น" *ไม่นับ* (ไม่งั้นคนที่ยังเข้าถึงบัญชีได้จะฝังคำตอบไว้กู้บัญชีคืนได้)

- ใช้ได้เฉพาะบัญชีบทบาท *สมาชิก* ที่ยังเปิดใช้งาน และเรียกจากเครื่องที่ติดตั้งเท่านั้น (loopback) · คำตอบเมื่อไม่ผ่านเป็นข้อความกลาง ๆ
- สมาชิกที่ยังไม่เคยเข้าระบบค้นด้วยรุ่นนี้ (ยังไม่มีชื่อ CRIMES ที่ตรวจพบ) ต้องให้ Super Admin ตั้งรหัสใหม่ให้ในหน้าสมาชิก
- กรอกผิดหลายครั้งถูกหน่วงเหมือนล็อกอิน · PASSCODE ของบัญชีถูกยกเลิกเมื่อตั้งรหัสใหม่ · มีรายการในบันทึกการตรวจสอบ
- ตั้งรหัสใหม่ทางไหนก็ตาม (ลืมรหัส · ผู้ดูแลตั้งให้ · เปลี่ยนเอง) **session อื่นทั้งหมดของบัญชีนั้นหลุดทันที** (คงผลข้ามการรีสตาร์ท)
- **Super Admin ไม่มีทางกู้รหัสด้วยตัวเอง** (วิธีวางไฟล์ของ v3.6.3 ถูกยกเลิกตามคำขอ) — ต้องมี Super Admin อีกคนตั้งให้

ข้อควรรู้: ถ้ามีใครตั้ง PASSCODE ไว้ หน้าเข้าสู่ระบบจะเปิดช่อง PASSCODE ก่อน — รหัสผ่านต้องกด **🔑 รหัสผ่าน** ด้านบนก่อน

## ปล่อยรุ่นใหม่

```bash
python tools/release.py extract                 # ครั้งแรก: แตก zip รุ่นล่าสุดลง build/
#   … แก้โค้ดใน build/CRIMES_AUTO_update/app/ …
python tests/run_all.py                         # ต้องผ่านทั้งหมด (ต้องมี Chromium: python -m playwright install chromium)
python tools/release.py build --version 3.6.0 \
    --notes "เวอร์ชัน 3.6.0 — หัวข้อแรก · หัวข้อสอง"   # [--open] ถ้าต้องการให้ทุกเครื่องอัปเดตได้
python tests/run_all.py --quick                 # ยืนยันสั้น ๆ หลังเลขรุ่นเปลี่ยน
git add -A && git commit && git push            # → เปิด PR → รอ CI เขียว → merge เข้า main
python tools/release.py verify                  # ดาวน์โหลดของจริงจาก GitHub มาตรวจ sha256
```

กติกาที่ `release.py build` บังคับ: สร้างจาก zip รุ่นก่อนแล้วแทนเฉพาะไฟล์ที่เปลี่ยน · รายการไฟล์ต้องเท่าเดิม
(ไฟล์ใหม่ต้องสั่ง `--allow-new-files` ซึ่งจะใส่ลง zip และตรวจเหมือนไฟล์อื่น · ไฟล์ที่เลิกใช้ตัดออกด้วย `--remove app/…`
และต้องใส่ชื่อไว้ใน `app/OBSOLETE.txt` ด้วย เพื่อให้ตัวอัปเดตลบออกจากเครื่องผู้ใช้) ·
ห้ามมีไฟล์จาก `tools/` หรือกุญแจใด ๆ · ทุก `.py` ต้อง compile ผ่าน · ฟังก์ชันแกนของหน้าแรกต้องอยู่ครบ
(กันเหตุ "อัปเดตแล้วเปิดมาเป็นหน้าดำ" ที่เคยเกิดใน v2.9.2) · เลขรุ่นต้องใหม่กว่าเดิม

`release.py verify` เทียบ manifest ออนไลน์กับในเครื่องทุกช่อง (version · url · sha256 · open) แล้วดาวน์โหลด zip
ที่ manifest **ออนไลน์** ชี้มาตรวจ sha256 — ผ่านก็ต่อเมื่อผู้ใช้ปลายทางจะได้รับของตรงกับที่ปล่อยจริงเท่านั้น

ข้อควรรู้: หลัง merge แล้ว URL `raw.githubusercontent.com` อาจยังส่งค่า manifest เก่าอยู่ **ราว 5 นาที** (แคช CDN)
ถ้ากด "ตรวจสอบอัปเดต" แล้วยังไม่เห็นรุ่นใหม่ ให้รอสักครู่ · ตรวจของจริงบน `main` ด้วย `release.py verify`

## ชุดติดตั้งตัวเต็ม (ตั้งแต่ v3.8.0)

ชุดอัปเดต (zip ด้านบน) มีแค่โค้ดโปรแกรม — เครื่องใหม่ต้องมี Python runtime และ Chromium อยู่ก่อน
`tools/build_installer.py` สร้าง **ชุดติดตั้งตัวเต็ม** ที่มีครบทุกอย่างในคำสั่งเดียว (ไม่ต้องมีเครื่อง Windows ตอนสร้าง):

```bash
pip install playwright==<รุ่นใน tools/installer/versions.json>
CRIMES_INSTALL_PASSWORD='…' CRIMES_SEED_PASSWORD='…' python tools/build_installer.py
#   → dist/CRIMES_AUTO_Setup_v<ver>/ + .zip (+ .sha256)   · dist/ ไม่ขึ้น git
```

- **ในชุด**: `app/` (โปรแกรมรุ่นล่าสุดตาม manifest · ตัดไฟล์ใน `app/OBSOLETE.txt` และแคชออก) · `runtime/` (Python embeddable + wheels
  ทั้งหมดสำหรับ win_amd64) · `browsers/` (Chromium ที่ Playwright รุ่นเดียวกับใน runtime ดาวน์โหลดเอง) · `Install.ps1` + `ติดตั้ง.bat` ·
  `Uninstall.ps1` + `ถอนการติดตั้ง.bat` · `icon.ico` · `install.json` · `seed_account.json` · `README-ติดตั้ง.txt`
- **สองรหัสตอนสร้าง** ให้ทาง environment variable (หรือพิมพ์ตอนถาม) เท่านั้น — ไม่มีที่ไหนในรีโป/ชุดติดตั้งที่เก็บรหัสจริง:
  `CRIMES_INSTALL_PASSWORD` = รหัสเริ่มติดตั้ง → แฮช PBKDF2-SHA256 ใน `install.json` (Install.ps1 ตรวจ ผิด 3 ครั้งเลิก) ·
  `CRIMES_SEED_PASSWORD` = รหัสผ่านบัญชี Super Admin เริ่มต้น (`Superadmin`) → แฮชแบบเดียวกับโปรแกรมใน `seed_account.json`
  ด่านตรวจท้ายสุดกวาดทุกไฟล์ในชุดเพื่อยืนยันว่าไม่มีรหัสเป็นข้อความธรรมดา
- **ติดตั้ง**: แตก zip → `ติดตั้ง.bat` → ใส่รหัสเริ่มติดตั้ง → ลง `%LOCALAPPDATA%\CRIMES-AUTO` (ไม่ต้องใช้สิทธิ์ผู้ดูแลเครื่อง)
  เครื่องที่มีอยู่แล้ว = อัปเกรด เก็บ `data/` `uploads/` เดิม สำรอง `data.db` ก่อน ลบไฟล์ที่เลิกใช้ ·
  สร้างทางลัดเดสก์ท็อป/Start Menu + รายการใน Settings → Apps · ติดตั้งหลายเครื่องแบบไม่ถาม: `Install.ps1 -Password … -Silent`
- **บัญชีเริ่มต้น**: เครื่องใหม่ (ยังไม่มี `data.db`) ได้ `seed_account.json` วางไว้ข้าง `db.py` → เปิดครั้งแรกโปรแกรมสร้าง Super Admin จากไฟล์
  แล้วลบไฟล์ทิ้งทันที (มีผู้ใช้อยู่แล้ว/ไฟล์เสียก็ลบ) · `/api/me` บอก `seed_password` และหน้าจอขึ้นป้ายเตือน "เปลี่ยนรหัสผ่านเดี๋ยวนี้"
  ทุกครั้งที่เข้า จนกว่าจะเปลี่ยน (ทางไหนก็ได้ — ป้ายเทียบแฮชกับที่จดใน `meta`) · **v3.10.0**: ถ้าเครื่องเชื่อมศูนย์กลางได้และองค์กรมีสมาชิกอยู่แล้ว
  โปรแกรม*ไม่*สร้าง Super Admin จากไฟล์นี้ (เครื่องเพิ่มเติมให้ผู้ใช้กด "สมัครใช้งาน" แทน — ดูหัวข้อ v3.10.0)
- **รหัสลับศูนย์กลางในชุดติดตั้ง (v3.10.0 — ไม่บังคับ · ปกติไม่ต้องใช้แล้ว)**: รหัสขององค์กรฝังในโปรแกรมแล้ว (`DEFAULT_HUB_TOKEN`) — ตั้ง `CRIMES_HUB_TOKEN='…'`
  (หรือ `--hub-token-file`) เฉพาะเมื่อชุดต้องใช้ศูนย์กลาง/รหัสอื่น → ชุดมี `hub_seed.json` ที่ Install.ps1 วางข้าง `server.py` เฉพาะติดตั้งใหม่ → เปิดครั้งแรกโปรแกรมใช้แล้วลบทันที (ค่าจากไฟล์ทับค่าฝัง)
  · `release.py` ห้ามไม่ให้ไฟล์นี้หลุดเข้าชุดอัปเดต · ด่านตรวจของตัวสร้างชุดยอมรับรหัสฝังใน `app/backend/config.py` เพียงจุดเดียว
- **ถอนการติดตั้ง** (Start Menu / Settings → Apps / `ถอนการติดตั้ง.bat`): ปิดโปรเซส → ถามยืนยัน `YES` → เสนอสำรองข้อมูลไว้ที่เดสก์ท็อป →
  ลบโฟลเดอร์ติดตั้งทั้งหมด (รวมฐานข้อมูลและแคช WebView2 `webview-data` ที่ v3.8.0 ย้ายมาไว้ในนั้น — ไม่แตะ `%LOCALAPPDATA%\pywebview`
  ที่โปรแกรม pywebview อื่นอาจใช้ร่วม) · ทางลัด · คีย์รีจิสทรี `HKCU\…\Uninstall\CRIMES-AUTO` · `~\.crimes_auto_profile` ·
  `%TEMP%\crimes_upd_*` · การติดตั้งแบบเก่าที่ `C:\Crimes-Automate` (ถ้าพบและยืนยัน) · สำรองไม่สำเร็จ = ยกเลิกทั้งหมด ไม่ลบอะไร
- **สร้างอัตโนมัติบน GitHub**: workflow `installer` (Actions → Run workflow) บน `windows-latest` ใช้ secrets
  `INSTALLER_GATE_PASSWORD` / `INSTALLER_SEED_PASSWORD` (+ `INSTALLER_HUB_TOKEN` ถ้าต้องการฝังรหัสลับศูนย์กลาง) แล้วอัปโหลด zip เป็น artifact (7 วัน)
  ⚠ รีโปนี้เป็นสาธารณะ — ใครที่ล็อกอิน GitHub ก็ดาวน์โหลด artifact ได้ และแฮชของรหัสสั้น ๆ เดาออฟไลน์ได้
  ทางที่ปิดกว่าคือรันคำสั่งข้างบนบนเครื่องผู้ดูแลเอง แล้วส่งชุดให้เครื่องปลายทางตรง ๆ
- รุ่น Python/Playwright/ชื่อบัญชีเริ่มต้น/รอบแฮชของรหัสเริ่มติดตั้ง อยู่ใน `tools/installer/versions.json` ·
  ทดสอบตัวสร้างด้วย `tests/test_installer.py` (จำลองการดาวน์โหลดทั้งหมด) · ตัวโปรแกรมด้วย `tests/test_v380.py`

## ไดเรกทอรีสมาชิกกลาง (ตั้งแต่ v3.7.0)

ทุกเครื่องที่เชื่อมศูนย์กลางใช้ **สมาชิกชุดเดียวกัน**: สร้าง/แก้/ปิดใช้งาน/ตั้งรหัสใหม่ที่เครื่องไหน ก็ใช้เข้าได้ทุกเครื่อง

- โปรแกรมส่ง *เฉพาะสมาชิกที่เครื่องนี้แก้* ขึ้นศูนย์กลางและรับของทั้งองค์กรกลับมาในคำขอเดียว (`kind="members"`) — คีย์คือชื่อผู้ใช้
  **ศูนย์กลางเป็นผู้ตัดสิน** ด้วยเลขรุ่น `rev` ต่อแถว (ไม่ใช้นาฬิกาของเครื่องใด): แถวที่ส่งต้องอ้าง rev ที่เห็นล่าสุด ไม่ตรง = มีคนแก้ก่อน → ของกลางชนะ
  และเครื่องนั้นได้ของกลางกลับไปทับ (แถบสถานะบอก "ถูกของกลางทับ") · คนที่ถูกลบมีป้ายหลุมศพ (`member_tombstones`) → เครื่องอื่น *ปิดใช้งาน* ตาม (ไม่ลบ กันประวัติกำพร้า)
- **สองรหัส** (ดู `tools/README.md`): รหัสลับ `HUB_TOKEN` อยู่ในรหัสเชื่อมต่อที่แจกทุกเครื่อง — ใช้ดึงไดเรกทอรีและส่ง *รหัสผ่านใหม่ของสมาชิกธรรมดา* (เปลี่ยนรหัสตัวเอง/ลืมรหัส) ได้เท่านั้น
  **รหัสผู้ดูแลศูนย์กลาง `ADMIN_TOKEN`** — จำเป็นสำหรับสร้างคน · แก้บทบาท/สิทธิ์/สถานะ/ชื่อ/อัตรา · ลบ · แตะบัญชี Super Admin
  **v3.13.0: ผูกกับบัญชี Superadmin ไม่ใช่กับเครื่อง** (ไม่มีช่อง 🔑 ในเครื่องไหนอีก — ดูหัวข้อ v3.13.0) · คนอื่นทำงานที่ต้องลายเซ็นผู้ดูแลไม่ได้ (403 ตั้งแต่ต้น ไม่ "ค้างส่ง")
  ยกเว้นตั้งรหัสผ่านใหม่ให้สมาชิกธรรมดา (ศูนย์กลางรับแบบไม่ต้องเซ็นอยู่แล้ว)
  ⇒ คนในที่อ่าน config.json ของเครื่องสมาชิกได้ จะเอารหัสร่วมไปตั้งตัวเองเป็น Super Admin หรือเปลี่ยนรหัสผ่านคนอื่นผ่านศูนย์กลางไม่ได้
- ศูนย์กลาง **ไม่รับการแก้ที่ทำให้ไม่เหลือ Super Admin ที่เปิดใช้งาน** (สองเครื่องปิดกันเองพร้อมกัน → คนหลังถูกปัดตก) และเครื่องแต่ละเครื่องก็ไม่ลดขั้น Super Admin คนสุดท้ายของตนตามไดเรกทอรีที่ไม่มีคนอื่น

## สมุดกองกลางกลาง (ตั้งแต่ v3.9.0)

เจ้าของโปรเจกต์สั่ง: *"ให้แสดงค่าเดียวกันทุกเครื่อง แต่สิทธิ์การแก้ไข Super Admin เป็นผู้จัดการ … ตั้งค่าแล้วให้จำค่าและซิงก์เองแบบออโต้ หน้าสมาชิกจะเห็นของตัวเองและทีมเท่านั้น"*

- หน้า **รับ/จ่าย กองกลาง** ไม่มีมุมมอง "เครื่องนี้/ทุกเครื่อง" อีกแล้ว — สมุดรับ/จ่ายซิงก์ผ่านศูนย์กลางเป็น**เล่มเดียวกันทุกเครื่อง** (ชีต `ledger`)
  หน้าจออ่านจากฐานข้อมูลในเครื่อง (ไม่ยิงศูนย์กลางทุก 8 วิ เหมือนมุมมองรวมแบบเก่าที่ขึ้น "The read operation timed out")
- โปรแกรมส่ง *เฉพาะรายการที่เครื่องนี้เพิ่ม/ลบ* (`kind="ledger"`, คีย์ `gid` · เจ้าของผูกด้วย **ชื่อผู้ใช้** เพราะ `user_id` ต่างกันแต่ละเครื่อง) พร้อม `after` = rev สูงสุดที่เคยรับ
  แล้วรับ **ส่วนต่าง** (rev > after) กลับมา — ไม่ใช่ทั้งเล่มทุกรอบ · rev ของชีตนี้เป็นเลขเดียวทั้งเล่ม (+1 ทุกการแก้) · ไม่ตรง = conflict ของกลางชนะ
- **Super Admin เป็นผู้จัดการ**: บันทึก/ลบได้เฉพาะ Super Admin (สมาชิกได้ 403 — เดิมใช้สิทธิ์ 'ตั้งอัตราค่าบริการ') และศูนย์กลางรับการแก้สมุดเฉพาะก้อนที่เซ็นด้วย `ADMIN_TOKEN`
  (ไม่มีข้อยกเว้นชีตว่างเหมือนสมาชิก) · **v3.9.1/v3.13.0**: Super Admin ที่ยังไม่ได้ใช้สิทธิ์ผู้ดูแล = ดูอย่างเดียว (403 ตั้งแต่ต้น ไม่ใช่ "รอส่ง") — "รอส่ง N" จะเกิดเฉพาะเมื่อ ADMIN_TOKEN ในสคริปต์ถูกเปลี่ยนหลังผูก
- **ขอบเขตการมองเห็น**: Super Admin (หรือสมาชิกที่ได้สิทธิ์ *ดูกองกลางทั้งองค์กร* — คีย์ `view_live` เดิม) เห็นทุกคน · สมาชิกเห็นยอด/รายคน/รายการ/กราฟ **เฉพาะของตัวเองและทีม** (`team_member_ids`)
  ทีมซิงก์ผ่านไดเรกทอรีสมาชิก (หัวข้อก่อนหน้า) จึงจัดจากเครื่อง Super Admin ครั้งเดียว มีผลทุกเครื่อง
- ลบ = แถวยังอยู่แต่ `deleted=1` (ป้ายหลุมศพ → เครื่องอื่นลบตาม) · รายการที่ยังไม่เคยขึ้นกลาง ลบทิ้งจริง · รายการก่อน 3.9.0 ได้ `gid`/`owner` ตอนเปิดโปรแกรมและถูกส่งขึ้นเป็นรายการใหม่
- ก้อน `counts` (ชีตยอดรายวัน) **ไม่มียอดรับ/จ่ายอีกแล้ว** — กระดานของศูนย์กลาง (`doGet`) คิดยอดเงินจากชีต `ledger` โดยตรง (ลบที่เครื่องไหนก็ไม่ค้าง ไม่ซ้ำ)
- เปลี่ยน URL ศูนย์กลาง = ลืมเลข rev ที่จำ · ศูนย์กลางที่ได้ `after` เกินกว่าที่เคยนับ (ชีตถูกสร้างใหม่) ส่งทั้งเล่มกลับ และรายการที่เครื่องเคยซิงก์แต่เล่มใหม่ไม่มี จะถูกส่งขึ้นใหม่
- **ตั้งค่าครั้งเดียว ซิงก์เอง**: Setting → ศูนย์กลาง บันทึก URL + รหัสลับ = เปิดใช้ทันที (ไม่มีติ๊กเปิด — ปิดด้วยปุ่ม "ปิดการเชื่อมต่อ") · ซิงก์ทุกรอบเวลา (ค่าเริ่มต้น 1 นาที) + ทันทีที่บันทึก/ลบ + ตอนเปิดหน้ากองกลาง + ปุ่ม 🔄
  ปุ่ม "ซิงก์เดี๋ยวนี้" ในหน้าตั้งค่าทำครบสามอย่างในคำขอเดียว (ตัวเลข · สมาชิก · สมุดกองกลาง)
- ศูนย์กลางต้องใช้ `tools/hub_gas.js` รุ่น **v3.9.0+** (ชีต `ledger`) — วางทับแล้ว **Deploy → Manage deployments → New version** · สคริปต์รุ่นเก่า → โปรแกรมแจ้ง "ศูนย์กลางรุ่นเก่า ยังไม่รองรับสมุดกองกลางกลาง"

## สมัครใช้งานเอง → Super Admin อนุมัติ (ตั้งแต่ v3.10.0)

เจ้าของโปรเจกต์สั่ง: *"แก้ไขโครงสร้างระบบสมาชิก ให้เป็นการสมัครและได้รับการอนุญาตใช้งานและสิทธิ์จาก Superadmin เท่านั้น ติดตั้งเสร็จแล้วในหน้าเข้าใช้งานให้มีปุ่มสมัครใช้งาน และใส่ URL กลางฝังไว้"*

  สมุดกองกลาง · ตัวเลขนับ จากศูนย์กลางได้ · ส่งคำขอสมัครปลอมได้ (เพดานค้าง 200) · และช่องทาง "ส่งรหัสผ่านใหม่ของสมาชิกธรรมดา" (v3.7.0 — จำเป็นต่อการเปลี่ยนรหัส/ลืมรหัสข้ามเครื่อง)
  ก็เปิดกับผู้ถือรหัสนี้เช่นกัน = คนนอกเขียนทับแฮชรหัสผ่านของ*สมาชิกธรรมดา*ได้ (บัญชี Super Admin แตะไม่ได้ — ต้อง `ADMIN_TOKEN` ซึ่ง**ไม่ได้ฝังและยังลับอยู่** · การอนุมัติสิทธิ์ทุกอย่างยังอยู่ที่ Super Admin)
  → ตั้งรหัสผ่านสมาชิกให้ยาว · จะปิดความเสี่ยงนี้เมื่อไรให้เปลี่ยน `HUB_TOKEN` ในสคริปต์ + `DEFAULT_HUB_TOKEN` แล้วปล่อยรุ่นใหม่ (หรือแจกรหัสทาง `hub_seed.json`/รหัสเชื่อมต่อแบบเดิม)
  · ชุดทดสอบปิดค่าฝังด้วย env `CRIMES_NO_DEFAULT_HUB=1` (ห้ามชุดทดสอบยิงศูนย์กลางจริง — `tests/_app.py` ตั้งให้เสมอ)
  · **v3.10.1**: ศูนย์กลางย้ายไป Deployment ใหม่ (ตัวเก่าค้างสคริปต์รุ่นเก่า อัปเดตทับไม่สำเร็จ) — URL ใหม่ฝังแทน และเครื่องที่ config ยังชี้ URL เก่าใน `config.OLD_HUB_URLS`
  ถูกย้ายให้อัตโนมัติตอนเปิดโปรแกรม (รหัสลับเดิม · เลขกองกลางที่จำไว้เกินของเล่มใหม่ → ศูนย์กลางตอบทั้งเล่มกลับมาปรับเองตามกติกา v3.9.0) · Deployment เก่าควรถูก Archive ทิ้งใน Apps Script

- **เริ่มค้นอัตโนมัติเป็นสวิตช์ ค่าเริ่มต้น "ปิด"** (เจ้าของโปรเจกต์สั่ง *"สถานะเริ่มต้นให้ปิดไว้ ไม่ต้องนับถอยหลัง"*): Setting → "เริ่มค้นอัตโนมัติเมื่อตรวจพบว่าเข้าสู่ระบบ CRIMES"

- **หน้าเข้าสู่ระบบมีปุ่ม "สมัครใช้งาน"** (`POST /api/register` — ไม่ต้องล็อกอิน): ชื่อผู้ใช้ 3–64 ตัว ไม่มีช่องว่าง · รหัสผ่าน ≥6 ยืนยัน 2 ครั้ง · ชื่อที่แสดง (ไม่บังคับ) ·

  (ลายเซ็นผิด → 400 พร้อมถอยค่าเดิมคืน ไม่ค้างสถานะ "เชื่อมแล้ว" ด้วยรหัสผิด) และได้ไดเรกทอรีทั้งองค์กรมาทันที · หน่วงต่อ IP เหมือนล็อกอิน (ผิด/สมัครเกิน 4 ครั้งติดกัน → 429)
  · เครื่องเดียวมีคำขอค้างเกิน 20 → 400 (กันสแปมในเครื่อง — ศูนย์กลางมีเพดาน 200 อีกชั้น)
- **คำขอ = แถวสมาชิก `pending=1 active=0 role=member` ไม่มีสิทธิ์/ทีม/อัตรา** ขึ้นศูนย์กลางด้วยรหัสร่วม (`_isSelfRegistration` ในสคริปต์ — แถวใหม่ที่เป็นแบบนี้เท่านั้น

- **ล็อกอินก่อนอนุมัติ** (รหัสถูก) → `403 {"pending": true}` "บัญชีนี้รอ Super Admin อนุมัติ" · รหัสผิด → 401 ธรรมดา (ไม่เผยว่ามีคำขอ) · เครื่องที่มีแต่คำขอยังถือว่า "ยังไม่ตั้งค่า" (`has_any_user()` ไม่นับ pending) แต่หน้าจอเป็นหน้าเข้าสู่ระบบ+สมัคร ไม่ใช่หน้าสร้าง Super Admin
- **Super Admin อนุมัติพร้อมให้สิทธิ์** ที่หน้า สมาชิก → การ์ด "คำขอสมัครใช้งาน" (ป้ายจำนวนบนเมนู · `/api/me.pending_requests` · `/api/auth/state.pending_users`):
  `POST /api/admin/members/<id>/approve` (ต้องยืนยันตัวใหม่ และ**ต้องเป็นผู้จัดการ** — v3.13.0: Superadmin ที่ใช้สิทธิ์ผู้ดูแลอยู่ เหมือนทีม/กองกลาง ไม่งั้น 403 `need_admin_token`
  เพราะผลอนุมัติจะค้างส่งไม่ถึงผู้สมัคร) ตั้งชื่อ/บทบาท/อัตรา/สิทธิ์แล้ว `pending=0 active=1` → ขึ้นกลาง → เครื่องผู้สมัครซิงก์แล้วเข้าได้ทันที (`summary.approved`)
  · ปฏิเสธ = ลบ (แถวลบขึ้นกลาง → เครื่องผู้สมัครปิดใช้งาน `pending=0 active=0` สมัครชื่อเดิมซ้ำเองไม่ได้ "ติดต่อ Super Admin") · ผู้จัดการสมาชิกที่ไม่ใช่ Super Admin แตะคำขอไม่ได้ (403) · `PUT active=1` บนคำขอ → 400 (ต้องใช้ปุ่มอนุมัติ)
- **เครื่องใหม่ตั้งตัวเองเป็น Super Admin ไม่ได้อีก** เมื่อองค์กรมีสมาชิกในศูนย์กลางแล้ว: `/api/setup` (หน้า "เครื่องแรกขององค์กร") ตรวจกับศูนย์กลางก่อนสร้างบัญชี — ด้วยรหัสเชื่อมต่อในฟอร์มหรือรหัสลับที่เครื่องมีอยู่ —
  มีสมาชิกอยู่แล้วและเครื่องนี้ไม่ได้ถือ `ADMIN_TOKEN` ตัวจริง (ศูนย์กลางตอบ `admin=false`) → `400 org_exists` "กด สมัครใช้งาน" · ติดต่อไม่ได้/สคริปต์รุ่นเก่า → ปล่อยตามเดิม (ไม่รู้ว่ามีใคร) · ศูนย์กลางว่าง → เครื่องแรกตามเดิม

## ยืนยันผลการค้นรายไฟล์ + ส่งไฟล์ผลขึ้น Google Drive (ตั้งแต่ v3.11.0)

เจ้าของโปรเจกต์สั่ง: *"เพิ่มโมดุลเมื่อค้นหาเสร็จสมบูรณ์แล้ว ให้มีช่องทางในการบันทึกและยืนยันผลการค้น ตามจำนวนแถวในไฟล์ที่ค้น และช่องทางสำหรับอัพโหลดส่งไฟล์ที่สมบูรณ์ไว้ในกูเกิลไดร์ฟ ที่ทำการเชื่อมต่อในการตั้งค่า (Superadmin เป็นผู้ตั้งค่าเท่านั้น)"*

- **สรุปผลรายไฟล์ (`file_results`)**: เมื่อไฟล์ถูกค้นจบรอบ (ทุกแถวมีผลหรือ ERROR) โปรแกรมสแกน*ไฟล์จริง*แล้วเก็บสรุป — ทั้งหมด/มีผล/**พบ/ไม่พบ**/เลขใช้ไม่ได้/ผิดพลาด/ยังไม่ค้น
  (จำแนกจากข้อความผลในคอลัมน์ F: `' - '` = ไม่พบ · `⚠` = เลขใช้ไม่ได้ · อื่น ๆ = พบ) · เก็บทั้งจาก worker ตอนค้นจบ และจากหน้าอัปโหลด/`queue/prune` (ไฟล์ที่ครบก่อนอัปเดตรุ่นนี้ก็เข้ารายการ)
- **การ์ด "ผลการค้นที่เสร็จแล้ว"** บนหน้าอัปโหลด: ปุ่ม **"✔ บันทึกยืนยันผล"** กดได้เฉพาะไฟล์ที่*ครบทุกแถวและไม่มีแถวผิดพลาดค้าง* (เซิร์ฟเวอร์สแกนไฟล์สดซ้ำก่อนรับ ไม่เชื่อตัวเลขเก่า)
  · จดเวลา+ผู้ยืนยัน (audit `file_confirm`) · ถ้าไฟล์ถูกค้นเพิ่ม/ผลเปลี่ยนหลังยืนยัน ตัวเลขใหม่จะล้างการยืนยันเดิม ต้องยืนยันซ้ำ · สมาชิกเห็น/จัดการเฉพาะงานของตัวเอง (Super Admin เห็นทั้งหมด)
- **ส่งขึ้น Google Drive ผ่านศูนย์กลางเดิม** (ไม่มี OAuth เพิ่ม): ปุ่ม **"⬆ ส่งขึ้น Google Drive"** โผล่เฉพาะไฟล์ที่ยืนยันแล้ว + ศูนย์กลางเปิดรับ — โปรแกรมส่งทั้งไฟล์ (base64, เพดาน 20 MB)
  ไปก้อน `kind="upload"` → สคริปต์เก็บลงโฟลเดอร์ในไดรฟ์ของบัญชีที่ Deploy สคริปต์ + จดชีต `uploads` (เวลา · เครื่อง · ผู้ส่ง · ชื่อไฟล์ · จำนวนแถว · ขนาด · sha256 · ลิงก์) แล้วตอบลิงก์ไฟล์กลับ
  · ชื่อไฟล์ที่เก็บ = `ชื่อเดิม(Nชื่อ).xlsx` เหมือนสำเนาใน Downloads · เครื่องสมาชิกส่งได้ด้วยรหัสร่วม (ไม่ต้องมีรหัสผู้ดูแล)
- **Superadmin เป็นผู้ตั้งค่าเท่านั้น**: บล็อก "📤 Google Drive" ใน Setting → ศูนย์กลาง (เห็นเฉพาะ Super Admin) — เปิด/ปิดการรับไฟล์ + ชื่อโฟลเดอร์ปลายทาง เป็น**ค่ากลางในชีต `config`**
  มีผลทุกเครื่องพร้อมกัน · การตั้งค่าต้องมาจากผู้จัดการ (v3.13.0: Superadmin ที่ใช้สิทธิ์ผู้ดูแลอยู่ — `POST /api/hub/drive` ติด `admin_required`+`fresh_auth`+`manager_required`)
  และสคริปต์ตรวจลายเซ็น `ADMIN_TOKEN` ซ้ำอีกชั้น · **ค่าตั้งต้น "ปิด"** — ยังไม่เปิดก็ไม่มีไฟล์ใดออกจากเครื่องไหนได้
- **ขอบเขตความเป็นส่วนตัว (ข้อยกเว้นที่เจ้าของสั่ง)**: ไฟล์ผลมีเลขบัตร+ผลคดี+ชื่อไฟล์เต็ม ๆ — ออกจากเครื่อง**เฉพาะเมื่อผู้ใช้กดปุ่มส่งเองทีละไฟล์** ไม่มีการซิงก์อัตโนมัติใด ๆ แตะไฟล์งาน
  (กติกาเดิมของก้อนซิงก์อัตโนมัติไม่เปลี่ยน — ดู "นโยบายข้อมูล") · HUB_TOKEN เป็นสาธารณะ จึงกันการยัดไฟล์ขยะด้วย: ต้องเปิดรับก่อน · เพดาน 20 MB/ไฟล์ · 40 ไฟล์/วัน · ชีต `uploads` จดทุกครั้ง
  · สคริปต์**ไม่มีช่องทางอ่านไฟล์กลับ** — ตัวไฟล์เปิดได้เฉพาะคนที่เข้าถึงไดรฟ์ของบัญชีเจ้าของสคริปต์

## สิทธิ์ผู้ดูแลผูกกับบัญชี Superadmin · ขั้นตอนหลัง login CRIMES ตามหน้าจอจริง · ถอดคู่มือ (ตั้งแต่ v3.13.0)

เจ้าของโปรเจกต์สั่ง: *"ขั้นตอนหลัง Login CRIMES ทำตามลำดับภาพที่มีกรอบสีแดง ภาพที่ 1 อาจจะไม่ขึ้นทุกครั้ง ไม่พบให้ทำลำดับต่อไปทันที ·
ทุกเครื่องที่อัพเดทนี้ต้องไม่มี 🔑 หรือถอดรหัสผู้ดูแลออกจากทุกเครื่อง ผู้ดูแลจะผูกอยู่กับ User คือ Superadmin เท่านั้น · ลบคู่มือที่แสดงอยู่ออกให้หมด"*

- **ขั้นตอนหลังเข้าสู่ระบบ CRIMES** (`engine.enter_classic_mode` — เรียกตอนรอ login · ตอนเริ่มรอบ · และใน `search_one_id` ก่อนค้นทุกแถว):
  1. กล่อง **"มีอะไรใหม่"** → กด **"เข้าใจแล้ว"** (`dismiss_announcement` — ไม่ขึ้นก็ข้ามทันที)
  2. หัวเว็บมีสวิตช์ **[ โหมดหน้าจอ (เดิม/ใหม่) ]** — เปิดอยู่ (สีฟ้า = หน้าจอใหม่ `#/iv/search/main`) → กดสวิตช์ให้เป็น **เดิม** (ปิดอยู่แล้วไม่กด · มีกล่องถามก็กด ยืนยัน/ตกลง *ในกล่องนั้น* · กันกดซ้ำถี่ 10 วิ)
  3. หน้า **"ระบบสืบค้น"** โหมดเดิม → คลิกการ์ด **"บุคคล"** (ทะเบียนราษฎร หมายจับ — เทียบข้อความทั้งก้อน "นิติบุคคล" ไม่โดน)
  4. หน้า **"โปรดระบุข้อมูล เพื่อทำการสืบค้นบุคคล"** → กรอกเลขบัตรประชาชน + ติ๊ก **คดีอาญา** แล้วค้นตามเดิม
  · ยังอยู่โหมดใหม่และสลับไม่ได้ → **ไม่ค้นแถวนั้นในโหมดใหม่** (ผิดพลาดแบบ "ลองใหม่" + เก็บภาพหลักฐาน) — หน้าโหมดใหม่ก็มีช่องเลขบัตร ต้องแยกให้ออกก่อนเสมอ
  · การรู้ว่า "login แล้ว" ต้องเห็นช่องเลขบัตร *และไม่อยู่ในโหมดใหม่* · `detect_account` ตัดข้อความสวิตช์ออกจากชื่อบัญชีที่จดไว้
- **ไม่มี 🔑 ประจำเครื่องอีกแล้ว**: เปิดรุ่นนี้ครั้งแรก `auth.load_config` **ถอด `hub_admin_token` ออกจาก config.json ทันที** (ทุกเครื่อง) — ค่าเดิมพักไว้ในหน่วยความจำของโปรเซสเท่านั้น
  เพื่อให้เครื่องของเจ้าของ (ที่เคยใส่ 🔑) ผูกให้บัญชี Superadmin อัตโนมัติเมื่อเข้าสู่ระบบด้วยรหัสผ่านครั้งแรก — ปิดโปรแกรมก่อนนั้น = หายไป (ผูกเองครั้งเดียวที่ Setting → ศูนย์กลาง)
- **ผูกกับบัญชี Superadmin**: `ADMIN_TOKEN` ถูกเข้ารหัสด้วยรหัสผ่านของ Superadmin (PBKDF2-SHA256 รอบเท่าแฮชรหัสผ่าน + HMAC-SHA256 แบบนับเลข + MAC — `auth.seal_admin_key`)
  เป็น "ซอง" เก็บในช่อง `permissions` ของบัญชีนั้น (คีย์ `_hub_admin` — ไม่ใช่สิทธิ์ที่ติ๊กได้) → ไปทุกเครื่องกับไดเรกทอรีสมาชิก **ไม่ต้อง Deploy สคริปต์ใหม่** (สคริปต์เก็บช่องนี้ตามที่ส่งมา)
  · Superadmin เข้าสู่ระบบ/ยืนยันรหัสผ่านที่เครื่องไหน → ถอดซองไว้*ในหน่วยความจำ*ของเครื่องนั้น (`_ADMIN_HOLDS`) → จัดการสมาชิก/ทีม/กองกลาง/อนุมัติ/ไดรฟ์ได้ทันที
  · ใช้ได้เฉพาะคำขอของ Superadmin คนนั้น (คนอื่นที่เข้าระบบพร้อมกันใช้แทนไม่ได้) · ออกจากระบบ / ปิดโปรแกรม / บัญชีถูกปิด-ลดขั้น / ซองเปลี่ยน = หายไปทันที
  · เข้าด้วย PASSCODE หรือ "จดจำการเข้าใช้งาน" หลังเปิดโปรแกรมใหม่ → หน้าจอขอรหัสผ่านหนึ่งครั้ง (`need_password`) แล้วทำต่อให้เอง
  · Superadmin เปลี่ยนรหัสผ่าน → เข้าซองใหม่ด้วยรหัสใหม่ ขึ้นกลางพร้อมแฮชใหม่ในแถวเดียวกัน · ลดขั้นเป็นสมาชิก → ซองถูกทิ้ง · ซองเปิดไม่ได้ (รหัสถูกตั้งจากทางที่ไม่ได้เข้าซองใหม่) → บอกให้ผูกใหม่ (`need_bind`)
  · ผูกเองครั้งเดียว: Setting → ศูนย์กลาง → **"ผูกสิทธิ์ผู้ดูแลกับบัญชี Superadmin"** (ADMIN_TOKEN + รหัสผ่านของบัญชี) — `POST /api/hub/admin/bind` ศูนย์กลางต้องยืนยันลายเซ็นของ*รหัสที่กำลังผูก*เอง ผิด = ถอยคืนทุกอย่าง
  · ความปลอดภัย: ซองเป็นสาธารณะเท่ากับไดเรกทอรี (HUB_TOKEN ฝังในโปรแกรม) — เดาซองได้ก็ต่อเมื่อเดารหัสผ่านของ Superadmin ได้ (เท่ากับแฮชรหัสผ่านที่ไดเรกทอรีมีอยู่แล้ว) **ตั้งรหัสผ่าน Superadmin ให้ยาวและเดายาก**
  · งานที่ต้องลายเซ็นผู้ดูแลจากคนอื่น (สร้าง/แก้ชื่อ-บทบาท-สิทธิ์-สถานะ-อัตรา/ลบสมาชิก · สมาชิกแก้ชื่อที่แสดงของตัวเอง) → 403 ตั้งแต่ต้น ไม่ทำในเครื่องแล้วค้างรอให้ Superadmin เซ็นทีหลัง
- **ถอดคู่มือที่แสดงอยู่ออกหมด**: ปุ่ม "📖 คู่มือการใช้งาน" บนแดชบอร์ด + หน้าต่างคู่มือ + CSS/ตัวจัดการ

## นโยบายข้อมูล (ศูนย์กลาง)

โปรแกรมส่งขึ้นศูนย์กลาง (Google Apps Script — ถ้าผู้ดูแลเปิดใช้):
- **ตัวเลขนับ**: จำนวนการค้นรายวันรายคน (รวม/พบ/ไม่พบ/ผิดพลาด) · จำนวนไฟล์ · ชื่อที่แสดง · รหัสเครื่อง · เวอร์ชัน · เวลาที่เห็นล่าสุด (ยอดรับ/จ่ายรายวันถูกตัดออกใน v3.9.0 — เงินไปทางสมุดกองกลางทางเดียว)
- **ไดเรกทอรีสมาชิก (v3.7.0 — เจ้าของโปรเจกต์อนุมัติ)**: ชื่อผู้ใช้ล็อกอิน · ชื่อที่แสดง · บทบาท · สิทธิ์ · สถานะ · รหัสผ่านแบบแฮช+salt · อัตราค่าบริการ · เวลาสร้าง/แก้ · เลขรุ่น (`rev`) ที่ศูนย์กลางกำหนด · (v3.9.0) ทีมที่สังกัด — ชื่อทีม + อัตราทีม · (v3.10.0) `pending` = คำขอสมัครที่รออนุมัติ · (v3.13.0) ซองรหัสผู้ดูแลที่*เข้ารหัสด้วยรหัสผ่าน*ของ Superadmin ในช่องสิทธิ์ (ไม่ใช่รหัสจริง)
- **สมุดกองกลาง (v3.9.0 — เจ้าของโปรเจกต์สั่ง "แสดงค่าเดียวกันทุกเครื่อง")**: รายการรับ/จ่ายทีละรายการ — เวลา · เดือน · ชื่อผู้ใช้เจ้าของ · ประเภท · จำนวน · **หมายเหตุที่ผู้ดูแลพิมพ์เอง** · ชื่อผู้ใช้ผู้บันทึก · ลบแล้ว · `rev`
  ⚠ หมายเหตุเป็นข้อความอิสระ — ห้ามพิมพ์เลขบัตร ชื่อผู้ถูกค้น หรือผลคดีลงไป (หน้าตั้งค่าเตือนไว้)

**ไม่ส่งออกจากเครื่องเด็ดขาด (การซิงก์อัตโนมัติทุกชนิด):** เลขบัตรประชาชน · ชื่อผู้ถูกค้น · ผลคดี/รายละเอียดคดี · ชื่อไฟล์งาน · รหัสผ่านตัวจริง · PASSCODE · KEY

**ข้อยกเว้นเดียว (v3.11.0 — เจ้าของโปรเจกต์สั่ง):** ปุ่ม "ส่งขึ้น Google Drive" ส่ง*ทั้งไฟล์ผลการค้น* (มีเลขบัตร+ผล+ชื่อไฟล์) ไปไดรฟ์ของหน่วยงาน — เฉพาะเมื่อผู้ใช้กดส่งเองทีละไฟล์ และเฉพาะเมื่อ Superadmin เปิดรับไว้ (ค่าตั้งต้นปิด) — ดูหัวข้อ v3.11.0

การเปลี่ยนแปลงใดที่เพิ่มฟิลด์ที่ส่งขึ้นศูนย์กลาง ต้องตรวจกับรายการนี้ก่อนเสมอ (ดู `backend/hub.py` — ALLOWED_FIELDS / PRESENCE_FIELDS / MEMBER_FIELDS / LEDGER_FIELDS)

## สิ่งที่รู้อยู่แล้ว / งานค้าง

- `app/backend/licensekey.py` ถูกตัดออกจากแพ็กเกจแล้วใน v3.8.0 (อยู่ใน `app/OBSOLETE.txt` — ตัวอัปเดตลบออกจากเครื่องผู้ใช้ให้) · คอลัมน์ `users.license_key` ยังอยู่ในฐานข้อมูลเพราะ SQLite ลบคอลัมน์ไม่คุ้มความเสี่ยง ไม่มีอะไรอ่านมัน
- ผู้ดูแลศูนย์กลางต้องวาง `tools/hub_gas.js` รุ่น **3.10.0 ขึ้นไป** (ชีต `members` + คอลัมน์ `pending` สำหรับคำขอสมัคร · ชีต `ledger` สำหรับสมุดกองกลางกลาง · ตั้ง `ADMIN_TOKEN` ให้ต่างจาก `HUB_TOKEN`) — ฟีเจอร์ส่งไฟล์ขึ้น Google Drive (v3.11.0) ต้องรุ่น **3.11.0** — แล้วอัปเดตด้วย **Deploy → Manage deployments → New version** (ห้าม New deployment — URL ที่ฝังในโปรแกรมต้องคงเดิม) — ดู `tools/README.md`
- เปลี่ยนชื่อทีมจากเครื่องอื่นที่ไม่ใช่เครื่องที่สร้างทีม → เครื่องที่สร้างจะเหลือทีมว่างชื่อเดิม (ไม่ลบทีมที่สร้างเองอัตโนมัติ) — ลบทิ้งเองได้ ไม่กระทบเครื่องอื่น
- ชุดทดสอบใช้เว็บ CRIMES *จำลอง* — พฤติกรรมกับเว็บจริงยังต้องยืนยันบนเครื่องผู้ใช้ทุกครั้งที่เว็บเปลี่ยนรุ่น
- เมื่อโปรแกรมเปิดไม่ขึ้นหรือค้นผิดพลาด หลักฐานอยู่ที่ `crash.log` (โฟลเดอร์ติดตั้ง) และ `app/backend/data/diagnostics/` (ภาพหน้าจอ+HTML ของแถวที่ผิดพลาด)
